# python/tatr/requirements.txt - the pinned environment for the TATR run-along.
#
# Captured 2026-09-01 from the validated environment on a compute node. This
# is to the Python side what renv.lock is to the R side, and it is watched
# by tools/securityScreen.ps1 for the same reason renv.lock is: compromising
# a dependency beats any application bug.
#
# INSTALL WITH tools/tatrProvision.sh, not by hand - torch and torchvision
# MUST come from the CPU index together. Installing torch from the CPU index
# and letting torchvision resolve from PyPI produces a version pair that
# imports and then dies at first use with "operator torchvision::nms does
# not exist". That happened on the first provisioning attempt and is why the
# provisioning script exists at all.
#
# transformers is pinned AT OR ABOVE 5.3.0 because 4.x is affected by
# GHSA-29pf-2h5f-8g72. An earlier version pinned BELOW 5 instead, because
# 5.x validates model configs strictly and rejects the published Table
# Transformer config ("Field 'dilation' expected bool, got NoneType"). That
# traded a known vulnerability for a loading convenience, which is the wrong
# way round. tatrTables.py::_config() corrects the config dict before
# construction instead - see its docstring. (CodeRabbit, PR #137.)
#
# Verified: both checkpoints load under 5.16.1 with the correct label sets,
# and the eight-article regression set returns identical table counts and
# shapes to the 4.57.6 baseline.
#
# The model weights are NOT here. They are pinned by revision SHA in
# tatrTables.py (DET_REV / STR_REV), fetched once by the provisioning
# script, and loaded thereafter with local_files_only=True so that no run
# reaches the network or can silently pick up new weights.
